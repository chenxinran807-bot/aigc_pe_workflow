# AI 试穿独立具名局部图输入实验设计

## 目标

验证局部放大是否能提升豆包 1.6 对发型、手部和服装细节的理解，同时避免 `contact-sheet-v1` 把多个视图拼进一张图后产生的图片角色混淆。

本实验只使用固定训练比较集中的 4 个定向 Case，不读取或运行验证集、测试集。人工标签只进入本地评测器，不向模型披露。

## 实验变量

模型、基线 Prompt、四维定义、输出 JSON 和后处理保持不变。唯一变化是给三张原图增加五张独立、具名的局部图：

| 输入变量 | 来源 | 用途 |
|---|---|---|
| `user_image` | 用户原图 | 人物整体参考 |
| `outfit_image` | 搭配原图 | 服装与场景整体参考 |
| `generated_image` | 生成原图 | 最终审核对象 |
| `user_face_detail` | 用户图上部裁剪 | 面部、发型和妆造参考 |
| `generated_face_detail` | 生成图上部裁剪 | 面部、发型和妆造比较 |
| `outfit_clothing_detail` | 搭配图中部裁剪 | 图案、Logo、文字、材质参考 |
| `generated_clothing_detail` | 生成图中部裁剪 | 服装细节比较 |
| `generated_hand_detail` | 生成图手部候选区域 | 手指和肢体自然度检查 |

首版不引入人体或手部检测模型。面部和服装使用确定性区域裁剪；手部图从生成图的中下部生成一个独立局部视图，变量名表示检查目的，不声称已完成手部检测。若手部不在该区域，模型必须依赖生成原图，不得把无手区域解释为异常。

## 数据流

1. 本地程序读取现有训练比较集和已下载原图，不输出内部图片 URL。
2. 每个 Case 生成五张局部 JPG，并记录只含 Case ID、角色名和本地路径的忽略清单。
3. 唯一 Coze 测试副本临时增加五个 Image 类型 Start 输入，并将其作为分别命名的图片变量传给同一个豆包 1.6 大模型节点。
4. 基线 Prompt 只补充输入角色说明和证据约束，不加入人工问题标签或 Case 特定提示。
5. 本地执行器上传三张原图与五张局部图，保存原始输出、结构化输出、输入版本和错误信息。
6. 本地评测器将结果与同一组人工标签比较。

## Prompt 约束

- 原图是主证据，局部图仅用于观察细节。
- 局部图与其来源原图属于同一图片，不是新的参考样本。
- 只报告能够在原图或对应局部图中明确定位的问题。
- 证据必须写明来源变量与可见区域，禁止占位符、二选一猜测和“可能/或许”式问题结论。
- 局部图未包含目标部位不等于目标部位异常；不确定时降低置信度，不编造问题。

## Coze 变更与恢复

变更仅发生在测试副本 `7668610423507419182`：增加五个 Start 图片输入并绑定到现有大模型节点。修改前记录当前三输入结构、模型和 Prompt；实验中不发布工作流；实验完成或发生输入绑定错误时恢复三输入基线。

不得修改原生产工作流，不写回飞书，不复制浏览器登录态。

## 停止与升级门槛

先运行两个已知手部 Case；任一输入缺失、变量错绑或模型把局部图当成独立样本时立即停止。通过后再运行发型和 Logo 两个 Case。

候选方案只有同时满足以下条件才进入剩余训练比较集：

- 4 个人工目标问题命中 4 个；
- 额外发现少于 `contact-sheet-v1` 的 17 条，并以原图基线的 12 条为改进目标；
- 不出现占位描述、二选一证据、来源变量错误或明显语义混淆；
- 四条运行均无输入失败。

额外发现继续记录为 `unverified_extra_finding`，未经人工审查不正式判为误报。未达到门槛则恢复三输入基线，不进入验证集，不建设 HTTP 服务。

## 自动化验证

- 单元测试覆盖五种局部角色的裁剪尺寸、边界和稳定命名。
- 请求构造测试确认八个输入角色完整且人工标签不进入 Coze。
- 文件上传测试确认局部文件覆盖对应变量，不影响原图角色。
- 全量测试必须通过，图片处理依赖不得存在高危安全公告。

## 非目标

- 不比较新模型，不启用模型协作。
- 不优化评分相似度，不新增历史数据以外的评审维度。
- 不运行冻结验证集和测试集。
- 不封装内部 HTTP 服务，不发布 Coze 工作流。
