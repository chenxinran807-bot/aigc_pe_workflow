# AI 试穿模型额外发现审查页设计

> **范围已收敛（2026-08-02）：** 审查页只是辅助 Prompt 设计的一次性工具。实际采用自包含临时 HTML、浏览器本地保存和 JSON 导出，不建设服务端结果库或通用标注平台。

## 目标

为训练集中的模型额外发现提供逐案例视觉审查能力。审查者同时查看用户图、搭配图、生成图、人工历史标签、模型问题与证据，并对每个额外发现独立判断：真实问题、模型误报或不确定。

审查结果用于优化豆包 1.6 视觉的 Prompt，在提高问题召回的同时控制误报。审查不会修改人工历史标签，不写回飞书，也不会发布 Coze 工作流。

## 范围

首版只覆盖固定训练比较集及其豆包 1.6 输出。验证集和最终测试集不进入人工审查页，避免冻结数据泄漏到 Prompt 开发过程。

页面支持：

- 逐案例查看三张图片；
- 同时展示人工四维问题标签；
- 展示模型额外发现、证据和所属维度；
- 对每个额外发现独立判定；
- 添加可选备注；
- 本地持久化审查结果；
- 汇总确认率、误报率和不确定率。

首版不支持：

- 修改人工真值；
- 自动写回飞书；
- 自动更新或发布 Coze Prompt；
- 多人协同、权限管理或审查冲突合并；
- 对冻结验证集和测试集进行标签查看或 Prompt 调试。

## 页面结构

采用“逐案例聚焦”布局。

### 顶部工具栏

- 显示当前 Case 序号、总数、已审和待审数量；
- 提供上一条、下一条；
- 支持筛选全部、待审、有额外发现、无问题样本；
- 显示当前模型和 Prompt 版本。

### 三图区域

按固定顺序并排展示：

1. 用户图：身份、发型、妆容参考；
2. 搭配图：服装、图案、Logo 和材质参考；
3. 生成图：最终审核对象。

图片使用等高自适应布局，保留完整画面；点击可打开大图查看细节。图片无法加载时显示明确错误，不允许将该 Case 标记为审查完成。

### 对照区域

左侧展示人工历史标注，按 face、pose、clothing、scene 分组。没有问题的维度明确显示“无已记录问题”。

右侧展示模型额外发现。每条发现包含：

- 所属维度；
- 模型问题名称；
- 模型证据原文；
- 真实问题、模型误报、不确定三个互斥选项；
- 可选备注。

每条发现必须独立判定，不能用整个 Case 的单一结论替代。

## 数据结构

审查输入由本地评测报告生成，不依赖浏览器读取飞书：

```json
{
  "caseId": "case-id",
  "images": {
    "user": "image-url",
    "outfit": "image-url",
    "generated": "image-url"
  },
  "humanIssues": {
    "face": [],
    "pose": ["主体手指/关节有轻微瑕疵"],
    "clothing": [],
    "scene": []
  },
  "extraFindings": [
    {
      "findingId": "stable-id",
      "dimension": "clothing",
      "label": "领口变形",
      "evidence": "生成图领口结构与搭配图不同"
    }
  ]
}
```

审查结果以独立本地文件保存：

```json
{
  "caseId": "case-id",
  "findingId": "stable-id",
  "verdict": "confirmed_issue",
  "note": "领口形状确有改变",
  "reviewedAt": "ISO-8601 timestamp"
}
```

`verdict` 只允许：

- `confirmed_issue`：图片证据支持模型发现；
- `false_positive`：图片证据不支持模型发现；
- `uncertain`：图片分辨率、遮挡或判断标准不足。

`findingId` 由 caseId、dimension、规范化 label 和 evidence 生成稳定哈希，保证重复导入不会产生重复审查项。

## 数据流

1. 读取训练比较集、人工标签和豆包 1.6 预测结果；
2. 复用现有评测器生成 `unverifiedExtraFindings`；
3. 组装审查页输入，不包含冻结验证集和测试集；
4. 页面读取审查输入与已有审查结果；
5. 用户逐条判定，服务端原子写入本地结果文件；
6. 汇总各维度确认率、误报率和不确定率；
7. Prompt 优化只使用人工标签和已确认的审查结论。

## 保存与错误处理

- 每次选择结论或修改备注后自动保存；
- 服务端写入临时文件后原子替换，避免中断造成 JSON 损坏；
- 保存失败时页面显示错误并保留未保存状态，不自动跳到下一条；
- 图片加载失败时允许重试，但不得提交该 Case 的完成状态；
- 原始模型输出和人工标签只读保存，审查结果放在独立文件；
- 内部图片 URL 不写入日志、Git 或页面错误详情。

## 统计口径

页面显示：

- 已审发现数 / 总发现数；
- `confirmed_issue` 数量和比例；
- `false_positive` 数量和比例；
- `uncertain` 数量和比例；
- face、pose、clothing、scene 四维分布；
- 每个问题规范标签的确认和误报分布。

未审项目不进入确认率和误报率分母。不确定项单独统计，不并入误报。

## Prompt 优化原则

采用平衡模式：

- 保留豆包 1.6 已经稳定命中的手指/关节检查；
- 加强发型、衣服边缘穿模、细微背景变化和 Logo/图案检查；
- 对审查确认的真实额外发现保留或增强；
- 对审查确认的误报加入更严格的证据门槛；
- 不使用不确定项直接修改 Prompt；
- 候选 Prompt 只有在训练集召回提升且确认后的误报没有明显恶化时，才进入冻结验证集。

## 测试

单元测试覆盖：

- 稳定 findingId；
- 只导入训练分区；
- 人工标签与模型输出保持只读；
- 三种 verdict 的校验；
- 重复保存覆盖同一 findingId；
- 统计分母排除未审项；
- 图片缺失时 Case 不可完成；
- 内部运行数据被 `.gitignore` 排除。

界面验证覆盖：

- 三图按固定角色顺序展示；
- 人工标签和模型额外发现同时可见；
- 每条发现独立选择且刷新后恢复；
- 保存失败和图片加载失败有明确状态；
- 上一条、下一条和筛选不会丢失审查结果。

## 验收标准

- 用户能完成当前 17 个额外发现的逐条审查；
- 每条发现都有唯一、可恢复的结论；
- 页面能导出按维度汇总的确认率、误报率和不确定率；
- 不修改人工标签、不写回飞书、不发布 Coze；
- 验证集和测试集不会进入审查输入；
- 全量项目测试通过。
